# Velore Fragrance Storefront & Admin

An English-only luxury fragrance storefront for Velore in Egypt. Customer orders are inquiries sent through WhatsApp; this project intentionally has no online payment, checkout, shipping-rate logic, customer accounts, newsletter, blog or i18n.

## Status

Phase 1 and Phase 2 are implemented, and Review Gate 1 was approved. Phase 3 (the owner-only admin) is in progress and must stop at Review Gate 2 for review. Phase 4 remains blocked until that gate is approved. The successful Atlas seed currently exposes nine clearly marked sample products, not verified Velore inventory; real catalog, product art and review data are still required before launch. See the seed notes below.

**Logo assets are temporary raster extractions. Replace with client-supplied SVG files.** The original client JPEG is preserved at `assets-source/VeloreLogo.jpeg`; the transparent PNG lockup, monogram, wordmark, favicon, touch icon and OG image are generated from it by `pnpm brand:assets`.

## Local development

```sh
pnpm install
cp .env.example .env
# Fill the credentials locally; never commit .env.
pnpm dev
```

The development server listens on `http://localhost:3000`. Without a reachable `MONGODB_URI`, public data-backed features show an explicitly labeled development/sample state; they do not imply that placeholder products are genuine Velore products. The login and admin APIs fail closed when owner credentials are not configured. The initial protected-DSN seed attempt failed at TLS negotiation, but the later idempotent retry completed and the public API verified nine products and five categories. If Atlas later becomes unreachable, check its cluster and Network Access configuration; never paste the DSN into chat or commit it.

Set `AUTH_COOKIE_MODE=local-http` only for plain HTTP on localhost; it uses `SameSite=Lax` without `Secure`. Use `preview` for the embedded HTTPS Manus Preview (`SameSite=None; Secure`) and `same-site` for the HTTPS Vercel site (`SameSite=Lax; Secure`). The default is `preview` so embedded Preview login works; set the mode explicitly for each deployment. Do not derive cookie attributes from `NODE_ENV` or the internal request scheme. Mutating admin requests require an exact browser-facing origin match in `AUTH_ALLOWED_ORIGINS` or `PUBLIC_SITE_URL`; add the Preview origin to the allowlist when it differs from the canonical site origin.

The Phase 3 utility `pnpm create-admin` prompts for a password and prints a bcrypt hash; place that hash in `ADMIN_PASSWORD_HASH` through a protected environment-variable input, not in source or chat. Run `pnpm typecheck`, `pnpm lint` and `pnpm build` after changes. Vitest and Playwright dependencies are prepared; Phase 4 will add and run the automated suites.

## Environment variables

| Name | Purpose |
| --- | --- |
| `MONGODB_URI` | MongoDB Atlas connection string. Use a strong, least-privilege database user scoped to the Velore database. |
| `JWT_SECRET` | Secret for the single owner's signed admin session; use a strong random value. |
| `ADMIN_EMAIL` | The single owner's email address. |
| `ADMIN_PASSWORD_HASH` | bcrypt hash generated by `pnpm create-admin`. |
| `AUTH_COOKIE_MODE` | `preview`, `same-site` or `local-http`; see the local development notes above. |
| `AUTH_ALLOWED_ORIGINS` | Comma-separated exact origins permitted for mutating admin requests. Needed when the request origin is not already the configured `PUBLIC_SITE_URL`, including an embedded Preview origin. |
| `PUBLIC_SITE_URL` | Explicit public origin used for canonical metadata, origin checks and absolute product URLs. Do not guess it. |
| `PUBLIC_WHATSAPP_NUMBER` | Digits-only international number with country code; placeholder is `20XXXXXXXXXX`. Do not use the placeholder to send orders. |
| `PUBLIC_INSTAGRAM_HANDLE` | Public Instagram handle; default placeholder is `velo.re15`. |

Never commit `.env` or real credentials. `.env.example` contains names and safe placeholders only.

## Seed/catalog placeholders

The idempotent seed script defines five fragrance families and nine clearly marked placeholder products (eight sample fragrances plus one discovery set), with every seeded record flagged `isPlaceholder: true`. The initial Atlas seed attempt failed during a TLS/transport handshake, but a later retry on 2026-10-21 completed successfully. The public API then returned nine products and five categories, and the `/shop` page visibly rendered the sample cards. These are demo entries, not verified Velore inventory, final prices or product claims. Before launch, replace sample products, images, notes, prices and reviews with client-approved materials; configure the real WhatsApp number and public origin. The supplied JPEG is kept unchanged in `assets-source/`; its transparent PNG outputs are temporary raster extractions. The approximate flame ribbon remains explicitly marked for replacement by the true brand vector. No customer order inquiries are stored in MongoDB.

If Atlas connectivity fails again, verify the cluster, least-privilege database user and Network Access rules for the actual runtime egress. Vercel's dynamic egress may require a broader allowlist such as `0.0.0.0/0` unless a static-egress option is configured; that materially increases network exposure, so only choose it knowingly and retain a strong, narrowly scoped database user. Never paste the DSN into logs or chat.

## Deploying on Vercel while keeping Manus push access

The project is currently connected to its Manus-managed repository; GitHub/Vercel connections have not been completed. To keep one source of truth, ask Manus to start the Webdev project's canonical-repository switch to GitHub. The owner-confirmed platform flow creates a new private GitHub repository and transfers the project. Do not add a personal access token to Git, source files or chat. After the switch completes, import that same repository from Vercel's **New Project** screen. This project already uses Astro SSR and `@astrojs/vercel`; keep the repository root as the project root and use the detected Astro build settings (`pnpm build`). See Vercel's [Astro deployment guide](https://vercel.com/docs/frameworks/frontend/astro) and [Git integration guide](https://vercel.com/docs/git).

For the review-gated workflow, do not make `main` Vercel's Production Branch: Manus checkpoint pushes update `main`, so that would deploy every checkpoint to production. Configure a separate release branch such as `production` as Vercel's Production Branch. Let `main`, `dev` and feature branches create Preview deployments, then update `production` only from a commit approved at the applicable review gate. If choosing `main` as Production Branch instead, every push to it will trigger production deployment.

Set Vercel environment variables separately for Preview and Production: `MONGODB_URI`, `JWT_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD_HASH`, `AUTH_COOKIE_MODE`, `AUTH_ALLOWED_ORIGINS`, `PUBLIC_SITE_URL`, `PUBLIC_WHATSAPP_NUMBER` and `PUBLIC_INSTAGRAM_HANDLE`. Use `AUTH_COOKIE_MODE=same-site` on the HTTPS Vercel site and set exact allowed browser origins. Do not put secrets in Git or bake them into the build. Use the real approved WhatsApp number and product data before accepting real inquiries. Atlas Network Access must permit Vercel runtime connections. A commercial Velore storefront must use Vercel Pro or Enterprise; [Vercel Hobby is for personal, non-commercial use](https://vercel.com/docs/plans/hobby).

After GitHub becomes canonical, Manus can keep committing and pushing to that same repository through its managed authorization. Vercel's Git integration is sufficient for automatic deployments; the optional Vercel connector is only needed if you want Manus to manage Vercel projects directly. It is currently disabled. For private-repository deployments, ensure the commit author also meets the Vercel project's access requirements described in its [Git guide](https://vercel.com/docs/git).

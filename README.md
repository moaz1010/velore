# Velore Fragrance Storefront & Admin

An English-only luxury fragrance storefront for Velore in Egypt. Customer orders are inquiries sent through WhatsApp; this project intentionally has no online payment, checkout, shipping-rate logic, customer accounts, newsletter, blog or i18n.

## Status

Phase 1 and Phase 2 are implemented, and Review Gate 1 was approved. Phase 3 (the owner-only admin) is in progress and must stop at Review Gate 2 for review. Phase 4 remains blocked until that gate is approved. Product records, product art and testimonials are still marked placeholders until Velore supplies real catalog and review data. The Atlas seed attempt did not complete; see the seed notes below.

**Logo assets are temporary raster extractions. Replace with client-supplied SVG files.** The original client JPEG is preserved at `assets-source/VeloreLogo.jpeg`; the transparent PNG lockup, monogram, wordmark, favicon, touch icon and OG image are generated from it by `pnpm brand:assets`.

## Requirements

- Node.js 22 or later
- pnpm 11.25.0 (`packageManager` is pinned)
- MongoDB Atlas M0 connection string for live product/category/settings data

## Local development

```sh
pnpm install
cp .env.example .env
# Fill the credentials locally; never commit .env.
pnpm dev
```

The development server listens on `http://localhost:3000`. Without a reachable `MONGODB_URI`, public data-backed features show an explicitly labeled development/sample state; they do not imply that placeholder products are genuine Velore products. The login and admin APIs fail closed when owner credentials are not configured. `pnpm seed` was attempted with the protected Atlas DSN but did not complete because of a TLS/transport handshake failure; some idempotent upserts may already have succeeded. Do not assume the database is fully seeded. After resolving Atlas/network connectivity, rerun `pnpm seed` to complete it safely.

Set `AUTH_COOKIE_MODE=local-http` only for plain HTTP on localhost; it uses `SameSite=Lax` without `Secure`. Use `preview` for the embedded HTTPS Manus Preview (`SameSite=None; Secure`) and `same-site` for the HTTPS Vercel site (`SameSite=Lax; Secure`). The default is `preview` so embedded Preview login works; set the mode explicitly for each deployment. Do not derive cookie attributes from `NODE_ENV` or the internal request scheme. Mutating admin requests require an exact browser-facing origin match in `AUTH_ALLOWED_ORIGINS` or `PUBLIC_SITE_URL`; add the Preview origin to the allowlist when it differs from the canonical site origin.

The Phase 3 utility `pnpm create-admin` prompts for a password and prints a bcrypt hash; place that hash in `ADMIN_PASSWORD_HASH` through a protected environment-variable input, not in source or chat. Run `pnpm typecheck`, `pnpm lint` and `pnpm build` after changes. Vitest and Playwright dependencies are prepared; Phase 4 will add and run the automated suites.

## Environment variables

| Name | Purpose |
| --- | --- |
| `MONGODB_URI` | MongoDB Atlas connection string. Use a strong, least-privilege database user scoped to the Velore database. |
| `JWT_SECRET` | Secret for the single owner's signed admin session; use a strong random value. |
| `ADMIN_EMAIL` | The single owner's email address. |
| `ADMIN_PASSWORD_HASH` | bcrypt hash generated by `pnpm create-admin`. |
| `AUTH_COOKIE_MODE` | `preview`, `same-site` or `local-http`; see the local development notes above. |
| `AUTH_ALLOWED_ORIGINS` | Comma-separated exact origins permitted for mutating admin requests. Needed when the request origin is not already the configured `PUBLIC_SITE_URL`, including an embedded Preview origin. |
| `PUBLIC_SITE_URL` | Explicit public origin used for canonical metadata, origin checks and absolute product URLs. Do not guess it. |
| `PUBLIC_WHATSAPP_NUMBER` | Digits-only international number with country code; placeholder is `20XXXXXXXXXX`. Do not use the placeholder to send orders. |
| `PUBLIC_INSTAGRAM_HANDLE` | Public Instagram handle; default placeholder is `velo.re15`. |

Never commit `.env` or real credentials. `.env.example` contains names and safe placeholders only.

## Seed/catalog placeholders

The idempotent seed script defines five fragrance families, eight clearly named placeholder products and one discovery set, with every seeded record flagged `isPlaceholder: true`. A seed attempt was made after the Atlas DSN was supplied, but it failed at a TLS/transport handshake and did not report successful completion; database state may be partial. Once Atlas/network connectivity is corrected, rerun `pnpm seed` and verify it completes. Placeholder reviews display as “Sample review” in development and are not presented as real in production. Before launch, replace sample products, images, notes, prices and reviews with client-approved materials; configure the real WhatsApp number and public origin. The supplied JPEG is kept unchanged in `assets-source/`; its transparent PNG outputs are temporary raster extractions. The approximate flame ribbon remains explicitly marked for replacement by the true brand vector. No customer order inquiries are stored in MongoDB.

For Atlas connection failures, verify that the cluster is running, the database user has least-privilege access to the Velore database, and the Atlas Network Access list permits the actual runtime's outbound IP. This Sandbox reported `ERR_SSL_TLSV1_ALERT_INTERNAL_ERROR` during TLS handshake with the replica-set nodes, so Atlas-backed queries and the seed cannot be assumed successful. Vercel's dynamic egress may require a broader allowlist such as `0.0.0.0/0` unless a static-egress option is configured; that materially increases network exposure, so only choose it knowingly and retain a strong, narrowly scoped database user. Never paste the DSN into logs or chat.

## Deploying on Vercel while keeping Manus push access

The current project is still connected to its Manus-managed repository; no GitHub or Vercel connection has been completed. To share one source repository safely, ask Manus to switch the Webdev project's canonical repository to GitHub. The platform's owner-confirmed flow creates a new private GitHub repository and transfers the project; do not add a personal access token to Git, source files or chat. After the switch completes, import that same GitHub repository into Vercel, choose `main` as the Production Branch, and keep feature branches for Preview deployments. Vercel's [Git integration](https://vercel.com/docs/git) builds on pushes; pushes to the configured production branch create Production deployments, while other branches create Previews.

Set the environment values in Vercel for the relevant Preview and Production environments before building: `MONGODB_URI`, `JWT_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD_HASH`, `AUTH_COOKIE_MODE`, `AUTH_ALLOWED_ORIGINS`, `PUBLIC_SITE_URL`, `PUBLIC_WHATSAPP_NUMBER` and `PUBLIC_INSTAGRAM_HANDLE`. Do not put secrets in Git or bake them into the build. A commercial Velore storefront must use Vercel Pro or Enterprise; [Vercel Hobby is for personal, non-commercial use](https://vercel.com/docs/plans/hobby). Configure MongoDB Atlas network access for the Vercel runtime and retain least-privilege database access.

Once the GitHub canonical switch is complete, Manus can keep committing and pushing to that same repository using the platform's managed authorization. The optional Vercel connector can be enabled if you want Manus to manage Vercel projects/deployments directly; it is currently disabled. Connecting Vercel to GitHub is sufficient for automatic deployments even without that connector.
